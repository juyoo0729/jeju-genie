## Phase 0. 데이터 확보 — 공공 API 대량 수집·발급

**목표**: 제주 관련 공공 데이터를 최대 폭으로 확보한다.

공공데이터포털(data.go.kr)에서 '제주'로 검색되는 API **417개를 전수 조사**하고
소스별로 활용신청·발급을 진행했다. 결과는 전부 엑셀(`지옥의 제주 api_분류.xlsx`)에 기록.

| 소스 | 발급 수 | 방식 |
|---|---|---|
| data.go.kr REST | 205 | 활용신청 (자동승인) |
| 제주데이터허브 | 93 | 프로젝트 담기 (projectKey 방식) |
| 제주도청 공개 API | 81 | 키 불요 |
| 서귀포시 공개 API | 25+ | 키 불요 |
| 기상청 API허브 | 40 | 활용신청 (SMS 인증 + CSRF 토큰 분석으로 발급) |
| 오피넷 유가 | 19 | 무료 키 (일 1,500건) |
| khug 주택도시보증 | 16 | API별 개별 키 발급 |
| 제주 ITS / C-ITS | 14 | 코드 발급 |
| 비짓제주 관광정보 | 1 | 발급 (https 필수) |
| VWorld 공간정보 | 1 | 발급 |
| **합계** | **약 397+** | |

**시도·실패·개선**
- 기상청 API허브의 활용신청 UI(iframe/모달)가 자동화로 동작하지 않음 → 신청 폼의
  실제 요청 구조를 분석해 CSRF 토큰 + XHR 헤더를 갖춘 직접 요청으로 발급 성공.
- 심의형이던 제주 ITS는 코드 발급 방식으로 확보. 일부(어린이집·홍수지도 등)는
  승인 심의가 필요해 보류 목록으로 관리.

## Phase 1. 코어 구축과 데이터 통합

**구조**: FastAPI(SSE 챗 + RAG) + React SPA + Chroma 벡터스토어 + Docker + Cloud Run + GCS.

- **커넥터 플러그인 구조**: `connectors/` 에 파일 하나 추가하면 데이터 소스가 하나 늘어난다.
  - `gov_content`(도청·서귀포 공개 API — 역사·방언·전시 등), `jejuits_tour`(ITS 관광지 1,136건),
    `visitjeju`(관광공사 콘텐츠), `jejudatahub`(데이터허브 제네릭), `seed`(직접 작성 개요)
  - 필드명이 소스마다 제각각인 문제 → `_extract.py` 공통 추출 유틸(제목/주소/좌표 자동 매핑)로 흡수
- **색인 결과**: OpenAI 임베딩(1536차원) 기준 **총 2,936 청크**
  (gov_content 1,115 + jejuits_tour 1,136 + visitjeju 600 + jejudatahub 80 + seed 5)
- **실시간 도구 레이어**: 색인하면 낡는 데이터(날씨·유가·교통·좌표·통계)는 LLM 함수호출로
  질의 시점에 조회하는 도구로 분리
- **컬렉션 분리 설계**: Chroma 컬렉션을 `jeju-<provider>-<model>` 로 임베딩 모델별 격리 —
  모델 교체 시 벡터 공간이 섞이지 않고 컬렉션 단위 재구축·롤백 가능

**시도·실패·개선**
- gpt-5 계열이 `max_tokens` 파라미터를 거부 → `max_completion_tokens` 로 프로바이더 계층 수정.
- 데이터허브 93개 중 통계형(400 응답)이 대부분이라 콘텐츠 색인은 80청크에 그침 —
  통계형은 색인 대신 `jeju_statistics` 실시간 도구로 돌려서 오히려 신선도가 좋아짐.

## Phase 2. 배포 정상화 — 첫 번째 큰 장애

**증상**: Cloud Run 라이브가 사실상 죽어 있었다. `/api/health` 가 `llm_provider: ollama,
index_chunks: 5` — LLM 도 인덱스도 로컬 폴백 상태.

**원인 분석**: CI 워크플로가 `--set-env-vars`(전체 치환)로 배포하면서, 값이 빈
OPENAI_API_KEY 하나만 주입 → 수동으로 넣어둔 전체 키가 매 배포마다 삭제됨 →
키가 없으니 ollama 폴백 + OpenAI 임베딩 컬렉션(2,936청크) 대신 seed 5청크만 조회.

**개선**:
1. Cloud Run 에 전체 키를 환경변수로 재주입 (값에 콤마가 있는 키 대비 커스텀 구분자 사용)
2. CI 를 `--update-env-vars`(병합) 방식으로 수정 + 빈 키 라인 제거 — 재발 원천 차단
3. 검증: `/api/health` = openai / 2,936청크, 커넥터 5종 enabled, 챗 RAG·도구 정상

## Phase 3 (07-08). 에이전트 전면 개편 — 품질 라운드 1~4

### 라운드 1: 스트리밍 tool-calling 에이전트 루프

**문제 인식 (사용자 피드백)**: 답변이 짧고 성의 없어 보임 / 응답이 느림 / 보유한
실시간 API 를 더 적극 활용하고 싶음.

**구조 개편**: 기존 3단계(RAG 프리페치 → 도구선택 비스트리밍 호출 → 답변 스트리밍,
LLM 왕복 3회)를 **단일 스트리밍 tool-calling 루프**로 교체.
- 도구가 필요 없으면 왕복 1회 만에 바로 토큰 시작 (첫 토큰 지연 대폭 감소)
- 필요하면 status 이벤트 송출 후 asyncio.gather 로 도구 병렬 실행 → 재호출 (최대 3라운드)
- RAG 도 `search_jeju_knowledge` 도구로 편입 — 모델이 필요할 때만 검색

**시도·실패·개선 (답변 잘림)**: 답변이 문장 중간에 잘리거나 빈 답변이 나옴.
원인 = gpt-5-mini 는 추론 모델이라 추론 토큰이 `max_completion_tokens` 예산을 잠식.
→ 1024 → 4096 확대 + `reasoning_effort=low`(속도 우선) 로 해결.

**시도·실패·개선 (RAG 노이즈)**: "가는 법/신청" 류 질문에 서귀포시 알림마당·민원서식
같은 행정공고가 검색 상위를 오염. → `NOISE_DATASETS` 필터를 정의해 색인·검색
양쪽에서 이중 차단.

### 라운드 2: 검색 도구·출처·지도 계약

- 검색 도구 2종 추가: `visitjeju_search`(관광 콘텐츠, 장소 질문 1순위),
  `jeju_wiki_search`(위키백과 — 축약 UA 는 403, 식별 가능한 UA 필수임을 실측)
- **도구 계약 도입**: 각 도구가 `refs`(참조 원문 URL)와 `map_points`(지도 좌표)를 남기면
  에이전트가 회수해 SSE 로 프론트에 전달 — 출처 칩과 지도가 우연이 아니라 계약이 됨
- **출처 필수 정책**: sources 이벤트는 항상 1개 이상 — 비면 질문 기반 검색 링크로 폴백
- 신규 API 3종: `/api/now`(기온 칩), `/api/live/summary`(실시간 패널), `/api/suggest`(후속 질문)
- UI 개편: Ocean Teal 팔레트, 사이드바, react-leaflet 지도 카드, 후속 질문 칩

### 라운드 3: 실시간 패널 세분화·밀집 지도·뉴스

사용자 피드백 5건 반영 (사이드바 세분화, 밀집 지도, 추천 코스, 뉴스, 마스코트/지도 카드 개선).

**시도·실패·개선 (스테일 데이터)**: 외국인 밀집 지도용으로 "중국인 카드소비" 계열
API 4종을 붙였더니 데이터가 2016~2018 에서 멈춘 스테일. → "읍면동 단위 외국인
단기체류 유동인구"(최신 2026-04)로 교체하고, 월간 데이터가 2~3개월 지연 게시되는
특성에 맞춰 최대 8개월 소급해 최신월을 탐색하도록 구현.

**시도·실패·개선 (프록시 페이징)**: 데이터허브 프록시는 필터와 page 파라미터를 섞으면
페이지가 넘어가지 않음(실측). → limit 파라미터(최대 100)로 읍면동 43곳을 일괄 수신.

### 라운드 4: 이스터에그·대화 기록·배포 장애 대응

- 영어 질문 → 영어 답변 + 마스코트 전환, "guten tag" 이스터에그(효과음 포함)
- 대화 기록: 새 대화 시 이전 대화가 사라지는 문제 → localStorage 자동 보관(20건) + 복원
- 유가 패널: 최저가 주유소 상위 7곳을 카카오맵 링크로 제공

**시도·실패·개선 (Cloud Run 한정 장애)**: 밀집 지도가 로컬은 정상인데 Cloud Run 에서만
빈 화면. 로그의 JSONDecodeError 로 원인 추적 — GCP 발신 IP 에 대해 상류 API 가
비JSON 응답을 반환. → 월별 소급 재시도 + 번들 스냅샷 폴백(폴백은 캐시하지 않아
상류 복구 시 자동 회복) + 비JSON 본문 앞 200자 로깅(원인 추적용).

## Phase 4 (07-09). 발표 준비 개선

- **순위형 추천**: 장소 추천 요청에 1곳만 답하던 것을 3~5곳 순위 제시(위치·특징·추천
  이유 포함)로 변경. 조건이 불명확해도 되묻지 않고 먼저 추천하도록 지침 보강.
- **장소 답변 지도 필수화**: 추천한 모든 장소의 좌표를 확보하도록 도구 지침 강화.
- **시도·실패·개선 (지오코딩 커버리지)**: "서귀포 찜질방" 같은 지역명+업종 조합 질의를
  VWorld 가 NOT_FOUND 처리(실측: '탐라사우나' OK, '서귀포 찜질방' 실패).
  → 지역어 제거 후 1회 재시도 로직 추가.
- **시도·실패·개선 (육지 오탐)**: 재시도가 육지의 동명 업소(부산 '온천랜드')를 잡아
  지도에 제주 밖 마커가 찍힘. → 제주 좌표 범위(위도 32.9~34.1, 경도 125.9~127.1,
  마라도~추자도 포함) 필터를 도구와 에이전트 양쪽에 추가.
- **시도·실패·개선 (도구호출 텍스트 누출)**: 모델이 도구 호출을 본문 JSON 텍스트로
  흉내 내는 사례 발견. → "도구 호출은 함수호출 기능으로만, 호출 턴에는 본문 금지"
  지침을 도구 가이드에 추가.
- 헤더 서브타이틀 "Everything about Jeju" 로 변경.
